# 太初灵契 · 正式美术与画面验收

这是实施规格与未完成项，不是成品验收证明。用户要求完整竖屏游戏，非原型、概念或简笔画；高精细手绘奇幻画面参考《圣兽之王》的清晰度与精细度，所有角色、场景、图标和音画资产必须原创或有明确许可。不得从参考游戏拆包或复制角色设计。

## 统一视觉语法

- 竖屏，左右阵营对峙，侧面偏三分之四、轻俯视。地面横向可读，不改成上下交战。
- 人物正常成年比例，脚落在同一视觉平面；轮廓分层为发型/肩部/武器/衣摆，避免职业只能靠文字区分。
- 笔触细腻、材质区分丝绸/皮革/金属/玉石；光源柔和明确，不能靠过度锐化和泛光伪造细节。
- 墨青、旧金与暖纸色为界面基调；控件既要精致也要可触达。小屏战场人物以轮廓和职业色识别，详情页展示原图细节。
- 人物背景真正透明，边缘无白圈、无裁切武器/头发/脚。统一身体显示高度，不按整张画布等宽强行拉伸；敌方镜像后文字/装备方向不产生明显错误。

## 制作和验收顺序

1. 人物设计和高精细全身原画；先补赤璃/叶流风职业辨识，随后给其他同职业人物独立资产，不能按职业复用宣布名册完成。
2. 统一比例、落脚点、武器边距与 alpha，生成引擎 SpriteFrame metadata，保留 UUID。
3. 实际游戏检查：720×1280 和常见长屏缩放；四人、六人、九人左右阵型；角色不重叠遮挡关键信息，姓名/生命值可读，详情页无拉伸。
4. 待机、攻击、施法、受击与倒下的动作/特效分层。当前整张静态图位移不是完整角色动画，不作为同等品质验收。
5. 法术目标与规则事件一致，音效与命中同步；控制同时特效数量、避免强闪烁。没有音频和动作实测时明确未完成。
6. 真实游戏截图与可重复交互验收，不用独立插画、静态排版或模型生成的假游戏截图替代。

## 实机参考拆解纠偏（2026-11-17，用户再次否定现画面）

本次逐张实际查看用户截图和官方实机图，不再以“精细手绘”一句话代替分析。参照：[世嘉战斗系统](https://asia.sega.com/unicorn-overlord/cn/system/stage-battle/)、[世嘉罗莎琳德实机](https://asia.sega.com/unicorn-overlord/cht/character/rosalinde/)、[PlayStation官方商店实机](https://store.playstation.com/ko-kr/product/HP0177-PPSA09894_00-UOMONARCHEDITION)。仅作为视觉分析，官方图片不纳入游戏资源或公开项目。

### 根因
用户截图把全阵和管理菜单常驻屏幕，角色只约屏高7%，文字贴亮山景，人物像悬空的列表头像。官方战斗以大角色、身体动作与命中为主体，环境有前中远景，完整阵位缩成底角小阵盘，界面退到边角与技能条。只换九张立绘、描边按钮和地面无法纠正这种构图类别错误。

### 新战中展示契约
- 仍只有Login/Game两场景。Game内区分战前整备和战中近景；开战收起招募/返回/养成表单。
- 720×1280竖屏：主交战角色身体约390–440设计像素（约30–34%画高）；角色比例按身体而非透明画布测量，保留武器完整。阵营保持我左敌右，不因敌方行动交换位置。
- 主舞台从y440延伸至-280；脚点错层约-170/-240。顶部仅简短关卡/阵营标识，技能条约y-300，底角两个小阵盘约y-430，展示完整队伍位置、存活、血量和灵力。小阵盘不硬塞九份微小姓名，焦点名字另清楚显示。
- 每次action起手至收势锁定镜头和体量；群攻只一次起手，主镜头最多数个受击者，阵盘标全体目标；治疗者与友军同侧，自疗一人。开场神通是一段统一施法，不逐伤害重复召唤。
- 命中先于死亡退场，退场完成再切焦点。大角色与阵盘消费同一实时事件状态，不能用最终HP或重新计算战斗。
- 战中背景不是77%空石地：中远景丰富、后沿约画高58%，下方横向落脚带，底角少量前景框景。已生成大空地背景只用于整备，不冒充近景舞台。
- 连贯动作、特效、镜头和精细UI仍逐项打磨。四关键姿势只是研发切片，不称商业级成品动画。

### 首轮视觉门槛
实际Creator390宽截图第一眼必须是人物交战舞台而非名单+按钮；主要角色脸与动作可读、脚点接地、背景层次不抢角色、UI不盖脸和武器。录看单攻、群攻、治疗、自疗、神通击杀、连续死亡切焦点六类，1×/2×及九人阵盘一致。单元测试通过不抵消视觉失败。最终品质仍未验收。

### 动作审查与下一轮母版（STAGE-02）

实际逐格查看四姿势图集，凌霄脸、冠、肩饰大体连贯，但举顶蓄力直接切水平突刺缺少落肘和转肩经过；双脚中点锚定不能保证接触脚不滑，收势与待机的重心也有跳变。因此不把四姿势命名为完整动作，不通过叠影淡化制造假补间。

下一轮研发锁定现有凌霄身份和第0格待机为母版，候选新立绘不混接。采用统一直刺路线：下沉→撤肘收剑→蹬地前送→伸展命中→撤剑→重心复位→衣摆消退。实验原图先放仓库外审查，不未经验证替换运行图集。固定格内记录根、左右脚接触、剑柄和剑尖；保持角色体积、剑长、衣片结构，不逐格缩放人体。命中由同一时间轴只触发一次，动作总时长须与事件等待预算一致。最终须两方向、1倍/2倍实际录屏检查接触脚、武器路线、首尾循环与命中，不以八格数量判定流畅。

资源预算只作估算：15b1d14 的20张PNG源图约34.37 MiB，按宽×高×4计算单份RGBA8共约120.01 MiB，不含mipmap、驱动或CPU副本；实际驻留需引擎与设备测量。保留高精细原图，不用盲目降分辨率掩盖品质问题。新舞台按当前区域请求，旧区域不应永久持有，登录页不应预载整套战斗资源。

### TYPE-01 标题字体与阅读边界

采用Noto Serif SC固定上游版本的OFL授权静态600子集，内部名称TaichuUISerifSubset。来源、复现及完整许可见tools/fonts/README.md及assets/resources/fonts，不把字体称原创生图资产。仅Login大标题、弹窗标题、招募纯角色名与两枚主要按钮使用；小字、伤害数字、血量混合文字仍sans。600字重不叠假粗体，缺字整段回退系统字体。离线390px字样仅支持方案选择，最终仍须真实Creator截图验证。字体打磨不代替动作、人物统一画风、场景和成品验收。

### 名册统一绘制语言复核（PRESENTATION-04并行）

当前是九名角色、五种职业机制，不宣称九个独立职业。逐张对照官方实机后，问题不只是像素：玄照皮肤/织物偏写实，夜无痕脸部偏写真，苏灵音/白凝霜/莲心亮衣与纹样密度过均；凌霄、岳沉山的大块面和轮廓更适合作为统一方向。后续维持身份和精细度，将细节放在受力衣褶、材质交接、金属分组和脸手重点，而非满身等强度织纹；不使用统一描边滤镜假装手绘。不同施法者必须通过重心、肢体和法器路线区分，而不只是立裙伸手。

仓库外赤璃绘制候选确实减少碎织纹、形成大明暗面，但仍沿用原静态姿势且杖顶/靴底留白不足。仅允许同引擎、同身体高度/脚点、同背景和朝向的受控A/B，需亮竹林和暗寺院、与凌霄/岳沉山同屏及有无特效对照；尚未实际运行，不能替换全名册并宣称统一通过。旧动作与新待机也不得因角色同名就混用。

战果与养成采用专用构图：战果保留结束的舞台与实际存活情况，不复活死者摆庆功姿势；以真实奖励、回合、存活和事件摘录传达结果，不造MVP/评分。指挥官用明确胸肩肖像窗和薄前景自然收口，不把半身原图当全身站在地面。两幅新增手绘界面材质须先检查真实透明像素和文本承载区，再在引擎验收。
